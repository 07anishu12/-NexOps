## 2. Forward Deployed Engineering (FDE) Requirements Mapping

| FDE Requirement | PRD Reference | Target Table | Columns & Enforcements | Verification Evidence |
| :--- | :--- | :--- | :--- | :--- |
| **FR-FDE-001 (P0)**: Customer workspace, site and environment implementation records | Section 14 & 16 | `fde_implementation_records` | `id`, `workspace_id`, `customer_name`, `site_reference`, `environment` (`development`, `staging`, `production`), `status` (`discovery`, `onboarding`, `staging`, `production`, `handover`, `closed`), `success_criteria`, `acceptance_owner` | Schema definition in `fde.ts`, table exists in public schema, composite unique `(workspace_id, id)` |
| **FR-FDE-002 (P0)**: Connector health tests and clear remediation steps | Section 14 & 16 | `deployment_readiness_checks` | `id`, `workspace_id`, `report_id`, `check_key`, `status` (`passed`, `blocked`, `warning`, `not_run`), `remediation_instruction`, `evidence_reference` | Schema definition in `fde.ts`, composite FK to `deployment_readiness_reports` |
| **FR-FDE-003 (P0)**: Readiness status with blocking and warning checks | Section 14 & 16 | `deployment_readiness_reports`, `deployment_readiness_checks` | `reports.status` (`ready`, `blocked`, `ready_with_warnings`), `checks.blocking` (`BOOLEAN NOT NULL`), partial index on `(workspace_id, status) WHERE blocking = true` | Check constraints, partial index coverage, composite FKs |
| **FR-FDE-004 (P0)**: Deployment stores agent version, environment, origin allowlist, feature config and policy snapshot | Section 14 & 16 | `deployments`, `deployment_origins`, `deployment_releases` | `deployments.active_version_id`, `environment`, `deployment_origins.origin` (unique), `deployment_releases.policy_snapshot`, `config_snapshot` | Strict foreign key references to immutable versions, unique origin index |
| **FR-FDE-005 (P1)**: FDE can compare configuration across staging and production | Section 14 & 16 | `deployments`, `deployment_releases` | Unique `(workspace_id, name, environment, channel)`, immutable JSON snapshots in `deployment_releases` | Composite uniqueness preventing colliding environments; immutable release snapshots |
| **FR-FDE-006 (P1)**: FDE can release new version to selected deployment and roll back | Section 14 & 16 | `deployment_releases`, `deployments` | `deployment_releases.release_number`, `rollback_of` UUID pointer, `deployments.active_version_id` update | Release number positive check, version FKs, instant pointer update semantics |
| **FR-FDE-007 (P1)**: Support access is time-limited, approved, reason-coded and audited | Section 14 & 16 | `support_access_grants` | `id`, `workspace_id`, `requested_by`, `approved_by`, `reason_code`, `scope`, `status`, `starts_at`, `expires_at`, check constraint `expires_at > starts_at`, check `approved_by NOT NULL` when active | Check constraints `expiry_after_start`, `approved_requires_actor`, partial index on active grants |
